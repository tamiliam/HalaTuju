## What Was Built

- **The whole admin console on the theme tokens**, minus the cockpit.
- **38 filled controls corrected to the brand** across 17 files.
- **Five category palettes** onto `category-N`, and **two states** resolved by weight.
- **`src/lib/roleBadge.ts`** — one copy of a mapping that had been declared three times.
- Guards for all of it, plus a repair to one that could never have fired.

## What Went Well

- **The category family paid for itself immediately.** F2c built it for four files; F4 found five
  more without any design work — roles, exam types, request components, platform-vs-organisation.
  The question "is this a state or a kind?" is now answerable in seconds, and the answer decides
  the token.
- **The closed-list guard behaved exactly as designed.** It failed the moment F4 added categorical
  files, forcing the addition to be explicit rather than silent. A guard that fails on intended
  work is only good if the failure is cheap and the intent is recordable — here it was both.
- **Re-deriving the file list found 44 files where the roadmap said 34.** Third sprint running that
  the plan's table has aged.
- **The `suspended` / `declined` cases resolved inside the vocabulary**, the same way `graduated`
  did in F3. Two sprints ago that needed inventing; this time it was a known move.

## What Went Wrong

1. **A guard was written that could never have fired.**
   *What:* the filled-control check was generated by a script. `\b` inside the script's own string
   became a **literal backspace byte (0x08)**, so the regex was "backspace, then text-white". It
   compiled, matched nothing, and reported success.
   *Why:* code that writes code has its escapes interpreted twice, and the failure mode is silent —
   not a syntax error, a dead test. Worse, the same session had already hit the sibling bug in F3b
   (`\s` in a template literal collapsing to `s`) and I still reached for a generator.
   *How it was found:* **bite-checking, and nothing else.** Three of four injected faults were
   caught; the fourth produced no failure at all, and chasing that discrepancy took about fifteen
   minutes of elimination — the file list was right, the per-file logic was right in isolation, and
   only a byte-level look at the line explained it.
   *System change:* the file was swept for control characters (one line, repaired by hand), the
   guard's escapes are hand-written with the reason beside them, and the lesson is recorded:
   **never generate a regex; write it, or the fault it is supposed to catch will be the one thing
   it cannot see.**

2. **A fault injection that did not land, which briefly looked like a second dead guard.** The
   swatch-collapse fault replaced only the first of four references, so the set still had two
   distinct swatches and the guard was correct to stay silent. *Lesson:* when bite-checking, assert
   the fault is present before concluding the guard is broken — half the confusion above was mine.

3. **A missing import slipped past jest and `next build`, and only `tsc` caught it.** The shared
   `roleBadgeClass` was imported into two of three files. `tsc --noEmit` went 24 → 25.
   *Why it mattered:* the "expect exactly 24" discipline from F2b is what made a +1 visible; a
   "fewer than before" check would have shrugged.

## Design Decisions

- **A role is a category, not a state**, so role badges take `category-N`. Recorded in the code.
- **The unknown-role fallback is GROUND**, not a swatch: "no role we recognise" is not a kind of
  person, and giving it a colour would make an error look like a valid eighth role.
- **One palette, one module.** Three files with a comment asking them to agree is not a mechanism.
- **`suspended` and `declined` are weight, not new hues** — consistent with F3's `graduated`.
